## 🤖 Инструкция для Claude (как продолжить вычитку в новой сессии)

Если ты — Claude в новой сессии без контекста: прочитай этот раздел и продолжай с первой лабы со статусом ⬜.
Пользователь скажет что-то вроде «продолжай вычитку».

### Общие правила (важно)
- **Методички НЕ редактировать.** Вычитка только собирает находки в `fixes/<лаба>.md`. Правки — позже, когда
  пользователь отметит варианты в разделах «✍️ Варианты решений» / «✍️ Решение по вычитке» и скажет «читай fixes».
- NestJS Lab — отдельная лаба с нуля, **с Vue Lab не связана** (решение пользователя).
- Команды держать простыми, без `$(...)` — иначе всплывают запросы разрешений, пока пользователя нет.
- Вычитку делают параллельные агенты модели **sonnet**. Одна лаба за раз. Перед запуском спросить у пользователя
  % лимита: лаба из 7 частей стоит ~16–24% сессионного лимита, из 2–3 частей — ~5–8%.
- Если пользователь говорит «останови», «контекст/лимит тратится» — сразу остановить агентов.
- Коммит и пуш — только когда пользователь попросит.

### Шаги для одной лабы
1. Нарезать методичку (из корня репо, папка вывода — во временной/scratchpad-папке, НЕ в репо):
   `python3 fixes/_tools/prep.py <лаба> <scratch>/proof-<лаба>`
   Имена лаб: nestjs, graphql, laravel, redis, docker, traefik, kubernetes, postgresql (пути к HTML — внутри prep.py).
   Скрипт печатает число частей (`part_NN.txt` по ~20 тыс. символов) и блоков кода (`pre_blocks.txt`).
2. Дописать в конец `fixes/<лаба>.md`: `\n---\n\n## 📖 Вычитка методички\n`
3. В таблице выше поставить лабе `🔄 идёт`.
4. Запустить агентов **в фоне, одним сообщением**: ~2–3 части на агента (таблица ниже). Каждому — свой диапазон
   частей и **своя** папка для временных файлов `<scratch>/proof-<лаба>-a`, `-b`, `-c`… (общую не делить — агенты
   затирали друг другу файлы). Промпт — шаблон ниже.
5. Когда все закончили — посчитать теги:
   `sed -n '/## 📖 Вычитка методички/,$p' fixes/<лаба>.md | grep -o '^- \*\*\[[^]]*\]' | sort | uniq -c`
6. Дописать в конец `fixes/<лаба>.md`:
   ```
   ### ✍️ Решение по вычитке
   - [ ] ⭐ A — исправить всё из вычитки выше
   - [ ] B — исправить только [тех] и [противоречие]
   - [ ] C — выборочно (отметь пункты выше)
   ```
7. В таблице: `✅ пройдено <дата>`, число находок и разбивка по тегам. Кратко пересказать пользователю главное.

### Шаблон промпта агенту
> Ты вычитываешь методичку <Лаба> (учебный документ на русском; стек: <кратко>). Ты агент <A/B/C>: вычитываешь ЧАСТИ <N…M>.
> Файлы (только читай): `<scratch>/proof-<лаба>/part_NN.txt` (оглавление — в начале part_01.txt), `<scratch>/proof-<лаба>/pre_blocks.txt`
> (все блоки кода с заголовками), исходник `<репо>/<лаба>/<файл>.html` (для сверки, не читай целиком).
> Временные файлы — ТОЛЬКО в `<scratch>/proof-<лаба>-<a/b/c>/`.
> Теги: **[тех]** — неверный код/вывод/команды/API/объяснения (можно проверить через node/tsc/docker, если уже есть локально;
> пакеты из сети не ставить); **[противоречие]** — текст противоречит сам себе (номера разделов, оглавление vs заголовки,
> имена файлов/функций, ссылки «см. раздел N»); **[текст]** — опечатки, латиница вместо кириллицы, сырые бэктики вместо `<code>`.
> Не придираться к стилю, только реальные ошибки.
> Читай каждую часть ЦЕЛИКОМ, не по диагонали. Сверяй код между шагами: имена файлов, переменных, функций, эндпоинтов,
> портов, env-переменных — то, что объявлено в одном шаге, должно так же называться в следующих. Проверяй, что команды и
> ожидаемый вывод соответствуют состоянию проекта на этом шаге (с учётом того, что читатель выполнял все предыдущие команды).
> Код, который можно проверить локально (node/tsc/php/python/bash -n/docker compose config), — проверяй. «Расхождений не найдено»
> пиши только после такой проверки и перечисли, что именно сверил.
> ПОСЛЕ КАЖДОЙ части дописывать (append, `cat >> … <<'EOF'`) в `<репо>/fixes/<лаба>.md`:
> `### Часть N (разделы X–Y)` и строки `- **[тег] Место** — «цитата» → в чём ошибка → как исправить.`
> (или `- — остальное в разделах X–Y проверено, расхождений не найдено.`). Файл не перезаписывать (туда пишут другие агенты),
> блоков «Решение» не добавлять, методичку не редактировать. В финальном ответе — только число находок по тегам на часть.
