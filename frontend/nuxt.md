### Перепроверка основной сессией (Claude Opus, вся методичка целиком)
Агенты (sonnet, 4 шт.) нашли 1 расхождение на 8 частей — меньше, чем в любой другой лабе, поэтому все шаги и разделы 1–10 перечитаны заново со сверкой по API Nuxt 4 / h3 / Docker и по сквозной нумерации данных (id обращений, содержимое статей).
- **[тех] (важно) Шаг 2.2, раздел 2.6, раздел 5.1** — «Два `useFetch` с одним URL получают один ключ: запрос один, данные общие», в ожидаемом результате «хендлер вызван ← один раз», «один и тот же ref? true» → автоматический ключ `useFetch` — это `hash([autoKey, url, опции])`, где `autoKey` компилятор подставляет по месту вызова (файл + порядковый номер вызова). Два вызова в разных строках получают разные ключи: хендлер вызывается дважды, данные не общие. Кроме того, в Nuxt 4 `data` каждого вызова — отдельная обёртка, так что сравнение `data === again` ненадёжно даже при общем ключе → шаг переписан на два варианта (автоключи → `false` и два вызова; явный `key: 'status'` → `true` и один вызов), сравнение `data.value === again.value`; в 2.6 и 5.1 сказано, что автоключ включает место вызова.
- **[тех] (важно) Шаг 6.4, Dockerfile** — «`COPY --from=build /app/server/db/migrations ./server/db/migrations    # их читает Nitro-плагин при старте`» → в Dockerfile комментарий допустим только отдельной строкой; `#` и слова после него уходят в аргументы `COPY` как лишние источники, и сборка падает («When using COPY with more than one source file, the destination must be a directory and end with a /») → комментарий вынесен на строку выше.
