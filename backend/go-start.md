- Код `session-1`, `session-2`, `session-3` перепроверен: `go build ./...`, `go vet ./...`, `gofmt -l .` без замечаний.
- Дополнительно проверены утверждения про `%w` и `%v`, nil-указатель в `error`, `os.Exit` и `defer`, поведение переменной цикла на `go 1.24` и `go 1.21`.

## Сессии 4–12: написаны без запуска

По вашему указанию код в этих сессиях **не запускался и не компилировался**. Это значит:

- Весь Go-код, SQL, Dockerfile, Compose, Makefile, workflow CI и `golangci-lint`-конфиг не проверены.

- В `session-8` … `session-12` нет `go.sum`; версии зависимостей выберет `go mod tidy`.

### С чего начать проверку (по убыванию риска)

1. **Компиляция.** В каждой папке `session-N`: `go mod tidy && go build ./... && go vet ./... && go test -race ./...`. Ошибки компиляции, если есть, будут в местах, где код собирался из кусков: `session-5` (разнесение по пакетам и переименование имён в заглавные), `session-7` (изменение `run`, флаг `ContinueOnError`, `errUsage`), `session-8` (вставка `runSimulation` в `main.go`), `session-10` (правки `cmd/api/main.go`).
2. **API сторонних библиотек.** `pgxpool.New`, `stdlib.OpenDBFromPool`, `pgx.ErrNoRows`, `goose.SetBaseFS` / `SetDialect` / `UpContext`, `errgroup.WithContext`: сигнатуры помнятся по версиям pgx v5, goose v3, x/sync; сверьтесь с pkg.go.dev.
3. **Тесты.** `TestRun` (сессия 7), `TestBarista*` (8), `TestErrors` и `TestOrderFlow` (9, зависят от поведения `ServeMux`, например `405` для неверного метода), тесты хранилища (10, нужна база `coffee_test`), `TestLoad*` (11).
4. **Docker и Compose.** Образ `golang:1.24` и тег `gcr.io/distroless/static-debian12:nonroot` (проверьте актуальный тег), порядок запуска с `service_completed_successfully`, healthcheck через `/api -healthcheck`, том PostgreSQL 18 в `/var/lib/postgresql`.
5. **CI.** Версии действий (`checkout@v4`, `setup-go@v5`, `golangci-lint-action@v8`) и формат `.golangci.yml` версии 2.
6. **Утверждения о версиях Go.** В тексте помечено «проверьте»: метод `WaitGroup.Go` (8.1), `encoding/json/v2` как эксперимент в 1.25 (6.4), дженерик-методы в 1.27 (6.1, взято из страницы спецификации go.dev).
7. **Ссылки.** Открыты только `go.dev/doc/install` и `go.dev/ref/spec`. Остальное проверьте `tools/check-links.sh`.
