### Часть 2 (разделы 3.1–6.1, сессии 3–5)

- **[тех] 5.3 bench/s5_list_vs_array.php** — «`$list = SinglyLinkedList::fromArray($arr);` … `SinglyLinkedList::fromArray(range(0, 99_999))`» → `fromArray` строит список через `append`, а тот по заданию O(n) (идёт до хвоста), значит `fromArray` — O(n²). Замер на PHP 8.5: 20 000 элементов — ≈2 с, 30 000 — ≈4,5 с, для 100 000 (замер памяти в конце скрипта) — около минуты и более; в «Ожидаемом результате» об этом ни слова, студент решит, что скрипт завис → в эталоне `fromArray` держать локальный `$tail` (`$tail->next = $node; $tail = $node;`) и пометить, что `append` через `fromArray` не вызывается, либо в бенче уменьшить n и честно написать про O(n²) конструирования.
- **[тех] 5.3 «память на 100 000: массив ≈ 4.0 МБ | список ≈ 6.0 МБ»** → замер даёт массив ≈ 2,0 МБ (range 100 000 = 131072×16 Б), список ≈ 8,5 МБ (≈2,5 МБ на 30 000 узлов, 80 Б на узел) — отношение ≈ 4×, а не 1,5×; оговорка «смотри порядок» есть, но пример занижает разницу → поправить на «≈2 МБ | ≈8 МБ».
- **[тех] 4.3 «очередь array_shift: 500.00 мс»** → при n = 100 000 array_shift даёт O(n²): на PHP 8.5 (3 прогона не нужны, один занимает) ≈4,6 с, т.е. в 9–10 раз больше; сам вывод «на порядки хуже SplQueue (≈4,5 мс)» верен, но цифра 500 мс не соответствует n = 100_000 (то же для 2.3: 40 000 → ≈730 мс вместо 160 мс, 1.5: array_merge 20 000 → ≈290 мс при заявленных 240 — тут норма) → пересчитать ориентиры (≈ 4–5 с) или уменьшить n до 30 000 и предупредить, что Bench::ms(…, 3) умножает время на 3.
- **[тех] 3.3 Ожидаемый результат (PHP 8.4 против 8.5)** → в 8.5 к Deprecated про float 1.9 добавляется второй: «Using null as an array offset is deprecated, use an empty string instead» (строка `$m[null] = 'f';`); в 8.4 его нет, так что ожидаемый вывод для 8.4 верен → добавить в примечание, что на 8.5+ будет ещё один Deprecated, а в коде вместо `$m[null]` писать `$m['']` с комментарием «null → '' (deprecated в 8.5)».
- **[противоречие] 4.3 вывод «стек array_push/pop»** → в коде стека используется `$s[] = $i` и `array_pop`, функции `array_push` нет → переименовать метку в «стек []=/pop».
- — остальное в разделах 3.1–6.1 проверено (запущено: TwoSum brute/hash, [5,5]/[5]/нет пары; Hashing; Brackets на 9 кейсах; UndoHistory; pop() пустого SplStack = RuntimeException; ключи 3.3 — в $m остаётся 3 элемента; бенчи 4.3/5.3; число assertions во всех блоках «OK (N tests, M assertions)»; цикл в 5.4 печатает ровно 13 значений, как в «Ожидаемом»; ссылки «сессия 8» (два указателя), «сессия 10» (приоритетная очередь), «сессия 13» (LRU) совпадают с картой разделов), прочих расхождений не найдено.

### Часть 3 (разделы 6.1–8.3, сессии 6–8)

- **[тех] 7.5 «Нашу quick из 7.4 такой гарантии нет — сравни ниже» / «сохраняется ли порядок?»** → quick из 7.4 раскладывает элементы по трём спискам `$less/$equal/$more` с сохранением порядка, т.е. на деле УСТОЙЧИВА (проверено на заказах с ключом `cat`: порядок id внутри категорий сохраняется, `2 4 7 1 3 5 8 6`). Студент, ожидающий «неустойчивость», получит обратное, а подсказка в тексте это не объясняет → переписать: «у quick такой гарантии нет в общем случае; наша версия устойчива только благодаря out-of-place разбиению, in-place (Ломуто/Хоара) — нет», либо дать задание реализовать in-place вариант и показать нарушение порядка.
- **[тех] 7.3 «OK (2 tests, 110 assertions) (число зависит от случайных данных…)»** → число assertions не зависит от данных: 5 фиксированных + 50 итераций = 55 на метод ×2 метода = 110 (и 220 для четырёх в 7.4, проверено). Пояснение про случайность неверно → убрать скобку.
- **[тех] 7.3 SortTest, `range(1, mt_rand(0, 40))`** → при `mt_rand` = 0 получается `range(1, 0)` = `[1, 0]` (range считает вниз), а не пустой массив; случай `[]` покрыт отдельно, но замысел «длина от 0» не выполняется → `$len = mt_rand(0, 40); $in = $len ? array_map(fn() => mt_rand(-50, 50), range(1, $len)) : [];` или `array_fill`/цикл.
- **[противоречие] 7.1 «Выбери один стиль границ … и не смешивай»** → в эталоне `find` использует закрытый интервал `[lo, hi]` (`$hi = count - 1`, `<=`), а `lowerBound` — полуинтервал `[lo, hi)` (`$hi = count`, `<`); комментарий «Полуинтервал» есть только у lowerBound → добавить к `find` комментарий «закрытый [lo, hi]» и фразу «два стиля ниже показаны намеренно», либо привести `find` к полуинтервалу.
- **[противоречие] Шаг 5.1 (часть 2) «Оба приёма встретятся в сессии 8 («два указателя»)»** → в сессии 8 (8.1 пара/дубликаты/палиндром сходящимися указателями, 8.2 окно, 8.3 префиксы) нет ни разворота списка, ни медленного/быстрого указателя (середина, Флойд) — они разобраны только в 5.1/5.4 → переформулировать: «идея двух указателей продолжится в сессии 8 (указатели навстречу, окно)».
- **[тех] 6.1 «Рост ≈ ×1.6 на каждый +1 к n … Каждое «+2» к n примерно утраивает время»** → 1.6² ≈ 2.6, а не 3; собственная таблица (3 → 8 → 20 → 55 мс) и замер на 8.5 (3.6 → 9.7 → 25 → 66) дают ×2.5–2.7 → написать «примерно ×2,6» (золотое сечение φ² ≈ 2,618).
- **[текст] 7.5 «Нашу quick из 7.4 такой гарантии нет»** → некорректная конструкция (нет подлежащего/предлога) → «У нашей quick из 7.4 такой гарантии нет».
- — остальное в разделах 6.1–8.3 проверено, расхождений не найдено: запущены fact/fibNaive (значения 75025/196418/514229/1346269, fib(6) вызывает fib(2) 5 раз), fibMemo/fibIter (fib(50)=12586269025; переполнение: fibIter(93) и fact(21) дают TypeError при strict_types, на 92/20 работают), s6_nobase (Fatal «Allowed memory size of 67108864 bytes exhausted», как в «Ожидаемом»), CategoryTree (20, глубина 4, путь, порядок после sort()), BinarySearch find/lowerBound (13 assertions), brokenA (-1) и brokenB (бесконечный цикл по трассировке; код 124 от timeout), все четыре сортировки против sort() (220 проверок), ожидания таблицы 7.4 по форме (пузырёк/вставки ×4, quick/merge ≈×2), `usort` в 7.5 даёт `2 4 1 3 5`, Pointers (3 теста, 6 assertions), Window (19, красный тест «19 is identical to 23», 5 assertions); различий PHP 8.4/8.5 в этих разделах нет.
