## Что найдено и исправлено при прогоне (22.10.2026)
**Ошибки генератора методички.** Повторные `### result` в одном шаге стирали предыдущий текст (в Prisma — 38 шагов, в Kubernetes — 40; Kubernetes пересобрана, тексты вернулись).

**Поведение Prisma 7 / PostgreSQL 18 отличалось от текста**
- `migrate dev --create-only` в Prisma 7 **всегда создаёт** файл (`-- This is an empty migration.`); «Already in sync» у него нет (4.5, 8.5, 11.2, 13.3, 14.x). Без `--create-only` при отсутствии изменений — «Already in sync».
- `@@ignore`-модель **попадает** в `migrate diff`: ручная дописка `tbl_DepositLog` в `0_init` (3.4) создавала дубль — убрана.
- `db pull` оставляет `tbl_DepositLog` с `@@ignore` и комментарием `///` (3.2).
- Незнакомое поле в `select` TypeScript **не ловит** (только `where`) — 4.7 переписан под `where`.
- `customer: { is: null }` = `cust_id IS NULL`, а не «осиротевшая бронь» (6.5).
- Для сирот-предметов служебный «Неизвестный предмет» породил бы 673 ложных пересечения из 806 — теперь `item_id = NULL` (11.1).
- Генерируемые колонки (`phone_norm`, `period`): без `@default(dbgenerated())` Prisma дописывает `ALTER COLUMN … DROP DEFAULT` в каждую автомиграцию, и она падает на shadow-базе (11.4, 13.3).
- GIN-индекс Prisma знает и хочет удалить, если он не описан: `@@index([name(ops: raw("gin_trgm_ops"))], type: Gin, map: "…")`; частичный индекс и индекс по выражению она не трогает (8.5).
- `prisma generate` без `--sql` стирает `sql.ts` TypedSQL; импорт — `../generated/prisma/sql.js`, не `sql/index.js`; скрипт `npm run generate` (9.5, 13, 14–18). `generate --sql` без папки `prisma/sql` падает.
- Типы TypedSQL: `bookings: bigint | null`, `revenue: Decimal | null` (9.5).
- В обёртке `$queryRaw` тип `void` не читается: `SELECT pg_sleep(1)` падает, нужен `SELECT 1 FROM pg_sleep(1)` (17.1–17.2).
- `\d` в тегированной шаблонной строке TypeScript превращается в `d` — регулярка не совпадает, `UPDATE` пишет `NULL`: нужны `[0-9]` (10.5).
- Миграция `REVOKE … ON "_prisma_migrations"` падала на shadow-базе: добавлена проверка `to_regclass` (16.2).
- `has_table_privilege('rental_app', 'tbl_Bookings', …)` без кавычек — ошибка регистра (16.2).
- Роль приложения не имеет `TRUNCATE`: в 17.5 `DELETE FROM event_log`.
- Скрипты, не импортирующие `db.ts`, не читают `.env`: `import 'dotenv/config'` (16.7, 17.1, 17.2).
- `autocannon` не разбирает кириллицу в URL: `%D0%B8…`; в окружении сборки `localhost` указывает на dind, поэтому адреса сервера — `127.0.0.1` (17.4, 17.7).
- OpenTelemetry: последние `sdk-node` 0.300 (api ≥ 1.10) и `sdk-trace-node` 2.x (api < 1.10) несовместимы — `ERESOLVE`; рабочий набор — `api@1.9.1`, `sdk-trace-node@2`, `instrumentation@0.223`, `@prisma/instrumentation`, трассировщик собирается из `NodeTracerProvider` (18.5). Имена span'ов — `prisma:client:*`, `duration` в микросекундах.
- `$transaction`: в логе запросов с адаптером нет `BEGIN`, есть `COMMIT` (7.1, 7.2, 12.1).
- Тесты и RLS (16 ↔ 18): под ролью `rental_app` фабрики не могут создавать данные (`new row violates row-level security policy`) — обычные тесты идут под владельцем, тесты изоляции берут `APP_DATABASE_TEST_URL` (18.1).
- Шаблонная база `--schema-only` не содержит справочников из миграций (счета `CASH/REVENUE/DEPOSITS`) — тесты заводят их сами (18.2).
- Сравнение времени: `createMany` против цикла — без прогрева первый замер врёт (7.3, 8.x); `timed()` не запускает функцию дважды.
- Production Hell (18.7): тест 4 при задержке 300 мс укладывался в порог — задержка 500 мс; тест 5 в пустой тестовой базе проходил вхолостую — добавлены данные; `scope.ts` использует клиент роли приложения с пулом из одного соединения.
- Эталонное решение 6.7 (3 запроса) — ≈25 мс вместо ≈135 мс; «12 секунд» на локальной базе не воспроизводятся.
- Числа в тексте приведены к фактическим: 133 пересечения (13.1), статусы, суммы проводок, `idle in transaction = 10` (12.5, 17.7), ~108 МБ памяти при обходе миллиона строк (17.5), шум миллисекунд в 8.x.

## Построчная вычитка и проверка «сверьтесь» (24.10.2026)
Ассистент прочитал все 19 сессий и справку по исходникам `prisma/src/*.md` рядом с записанным выводом прогона (22.10), затем проверил запуском в отдельном Docker (PostgreSQL 18, Node 24, Prisma 7.10.1, PgBouncer 1.26.1) все места с пометкой «сверьтесь». **Найдено и исправлено:**
- **3.6** — текст говорил, что `db pull --print` вернёт `tbl_DepositLog` без `@@ignore`; на деле `@@ignore` Prisma **сохраняет** из прежней схемы (в записанном выводе он есть). Шаг переписан: ключ виден, `@@ignore` снимаем руками.
- **7.6 / справка** — с адаптером `pg` у `P2002` **нет `meta.target`**: имя ограничения лежит в `meta.driverAdapterError.cause.constraint.index`; код `DuplicateError` из лабы получал пустой список полей. Переписаны `mapDbError`/`DuplicateError`, добавлена `constraintOf`; `P2025` теперь берёт `meta.modelName` (поля `meta.cause` нет).
- **11.5** — после отката drift был второй, дублирующий блок «Сделай выход №1» (повторный `DROP COLUMN manager` падал с `column does not exist`); блок удалён, ключи `outputs.json` сессии 11 сдвинуты; добавлено пояснение, что `migrate status` ещё сообщает про неприменённую `…_customer_phone_unique` из 11.4.
- **12.1** — в логе с адаптером `pg` нет строк `BEGIN` (только `COMMIT`/`ROLLBACK`), текст и `grep` исправлены.
- **18.4** — **образ не стартовал**: сгенерированный клиент импортирует `./internal/class.ts`, `tsc` оставлял суффикс `.ts`, контейнер падал `ERR_MODULE_NOT_FOUND`. В `tsconfig.build.json` добавлен `rewriteRelativeImportExtensions: true`; образ собран, `HEALTHCHECK` зелёный, процесс под пользователем `node`.
- **17.3 (PgBouncer)** — запущен: образ `edoburu/pgbouncer` с `POOL_MODE=transaction` работает с Prisma 7.10 (60 параллельных запросов = 5 серверных соединений); локальный `set_config(…, true)` безопасен, сессионный `false` остаётся на серверном соединении; добавлено `AUTH_TYPE: scram-sha-256` (PostgreSQL 18 хранит пароли в scram, с md5 по умолчанию «wrong password type»); при `max_prepared_statements=0` адаптер `pg` тоже работает.
- **6.2 / 6.3 / 6.4** — вложенный `take` при стратегии `query` применяется **в памяти** (в SQL нет `LIMIT`); одинаковые `findUnique` в одном тике склеиваются в один `IN`; `relationLoadStrategy` без `previewFeatures = ["relationJoins"]` падает `PrismaClientValidationError`.
- **7.1** — «родной» `upsert` (`ON CONFLICT`) только если в `where` одно уникальное поле, то же значение есть в `create` и нет вложенных записей; в примере лабы — `SELECT` + `UPDATE/INSERT` + `COMMIT`.
- **8.4 / 8.7** — `Gin` на обычной строке отвергается; частичные индексы в схеме — только с preview `partialIndexes`; при collation `en_US.utf8` обычный B-tree **не** помогает `LIKE 'Иван%'` (нужен `text_pattern_ops`), текст «ожидаем: только `startsWith`» исправлен.
- **15** — `$use` в Prisma 7 нет; расширения `query` действуют внутри `db.$transaction`; `include` с `where` для связи «к одному» и `_count` с `where` работают.
- **18.3** — `migrate diff --from-config-datasource --to-schema … --exit-code`: ручные индексы (частичные, по выражению), `CHECK`, `EXCLUDE`, триггеры ложных расхождений **не дают**; лишний столбец (в т. ч. генерируемый) — даёт `DROP COLUMN` и код 2.
- Прочее: убрана устаревшая пометка «не прогонялось» из «Как проходить»; опечатка «ТS-мире»; пометки «сверьтесь» заменены проверенными фактами (в справке остались пояснения про сами пометки).
