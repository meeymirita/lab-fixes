## Решение по вычитке — исправлено 04.10.2026 (полномочия «на усмотрение», критерий: запускается и верно, без придуманного)

Проверено запуском: compose из шага 1.1 проходит `docker compose config`, образы `nginx:1.30`, `postgres:18`, `redis:8` существуют; `work(50_000_000)` на `php:8.4-cli` в Docker даёт **922688**, 453 мс без JIT и 222 мс с JIT (в методичке было 123456 / 900 / 250 и «в разы»).
- Версии: `postgres:18` (том `pgdata:/var/lib/postgresql`), `redis:8`, `nginx:1.30` (compose, таблица раздела 3, Dockerfile.prod).
- 3.2: запросов ≈ 61 (1 + 20 + ≈40 позиций), формула исправлена. 2.1: smoke даёт ≈16 запросов, а не 40.
- 2.2/2.5: в выводе добавлена строка `orders` (✓), p95 `/api/orders` в таблице «ДО» — 480 мс (при пороге 500 прежние 540 противоречили выводу). `stress.js` → `scenarios.js`; примечание про `sed -i` на macOS; Debugbar включается по `APP_DEBUG`, не по `local`.
- 3.3: ошибка lazy loading видна только при `APP_DEBUG=true`; `/catalog` тоже упадёт — дана правка. 4.2: «Конец сессии» посреди сессии 4 переименован в «Уборка». 4.3: flamegraph — корневой блок равен всему запросу, ищем листовые широкие. 4.4: формат ответа отчёта изменился (оговорено).

## 🧪 Сухой прогон — 04.10.2026 (Docker Desktop на macOS) — ЧАСТИЧНЫЙ: сессии 1–6 и шаги 7.1–7.2
Стенд собран вне репозитория по блокам методички: `php:8.4-fpm` + nginx 1.30 + PostgreSQL 18 + Redis 8, Laravel 13.17, 1 000 000 заказов, k6, Debugbar, Telescope, SPX, OPcache/JIT, кеш с тегами и блокировками, индекс + `EXPLAIN`, Octane на FrankenPHP. Контейнеры ограничены по CPU отдельным compose-override (только в моём прогоне). Прогон остановлен по просьбе пользователя (нагрев ноутбука, затем лимиты).
**Работает как написано:** сессия 1 (стенд, сид, эндпоинты, перцентили, `ab`), 2 (k6: smoke/load/stress/spike, код 99), 3.1–3.3 (Debugbar 51 запрос, `/api/orders` 61 запрос, `preventLazyLoading` падает с тем же сообщением, после `with()` — 3 запроса), 4.1–4.4 (SPX, профили, правка отчёта), 5.3–5.5 (`v1 v1 v2`, JIT), 6.2 (`env()` = null после `config:cache`), 6.5 (Seq Scan → Bitmap Index Scan, 49 → 17 мс), 7.1 (1139 против 23 мс), Octane поднимается (4 мс на запрос после прогрева).
**Найдено и исправлено в методичке:**
- **[тех] 1.2:** сидер без `use DB` падал с `Class "Database\Seeders\DB" not found`.
- **[тех] 2.1/2.2:** формат вывода k6 изменился (`0 out of 24`, блок THRESHOLDS); число запросов в smoke — 24, не 16.
- **[тех] 3.4:** выключение Telescope RPS не меняет (≈ 20 в обоих режимах), ожидаемые «25 → 90» не воспроизвелись — переписано честно (Telescope пишет запись на каждый запрос: проверяется `telescope_entries`).
- **[тех] 4.2:** метрика CPU time в SPX включается `SPX_METRICS=wt,ct,zm`; у `/api/lab/sleep` CPU ≈ 10 мс, не 1–3. **4.3:** список «самых тяжёлых» функций заменён реальным (Eloquent: `Str::is`, `resolveClassAttribute`, `getCasts`; затем SQL и Carbon). **4.4:** цифры «было/стало» 5,4 → 40 RPS.
- **[тех] 5.1–5.2: в актуальном образе `php:8.4-fpm` OPcache уже установлен и включён** — «OPcache не установлен» и сценарий «ДО/ПОСЛЕ установки» неверны. Переписано: «ДО» получаем выключением (`opcache.enable=0` через смонтированный `zz-opcache.ini`), `restart` вместо пересборки; на нашем стенде 13 → 19 RPS (×1,5). 5.3/5.5 — тоже `restart`; 5.5: JIT на веб-запросах в пределах шума (17,5/17,8 RPS).
- **[тех] 6.1: в Laravel 13.17 `route:cache` сериализует замыкания** (`laravel/serializable-closure`), ошибки `Unable to prepare route … Uses Closure` нет — шаг переписан; кеши конфигов/маршрутов на нашем стенде скорость не меняют.
- **[тех] 6.3 (самое важное): кеширование `Collection` ломало отчёт** — в Laravel 13 `cache.serializable_classes = false`, на втором запросе из кеша приходит `__PHP_Incomplete_Class` и 500. `computeReport()` теперь возвращает массив (`->map(fn ($row) => (array) $row)->all()`), пояснение в «Зачем». **6.4:** давка на быстром отчёте нестабильна (без блокировки 1, 3, 3; с блокировкой всегда 1) — оговорено. **6.5:** цифры EXPLAIN 49 / 17 мс.
- **[тех] 7.2:** тега `dunglas/frankenphp:latest-php8.4` не существует — заменён на `1-php8.4`.
