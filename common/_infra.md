**Воркер прогресса и CORS (05.10.2026):** методички открываются с `meeymirita-files.storage.yandexcloud.net`, поэтому воркер должен разрешать и этот адрес (список `ORIGINS` в `tools/progress-worker/worker.js` + переменная воркера `EXTRA_ORIGINS` в Cloudflare; копия кода в панели вручную). Симптом, если не так: в методичке «нет связи с Worker», а на `works/progress.html` всё работает.

**Пароль на /mira/ (05.10.2026):** вход через форму `/mira-login/` (файл `site-private/mira-login/index.html`, публичный), логин `mira`, пароль выбирает пользователь (в репозитории и в `CLAUDE.md` его нет). Проверка — Caddy: `POST /mira-api/login` с `Authorization: Basic` (bcrypt-хеш), при успехе `Set-Cookie: mira_session=<случайный ключ>`; без cookie `/mira/*` → 302 на форму; `/mira-api/logout` сбрасывает cookie. Ставит/меняет `deploy/protect-mira.sh` на сервере (пишет `/etc/caddy/mira-auth.conf` с правами `root:caddy 640` — Caddy работает под пользователем `caddy`!, и вставляет `import` в блок anitech после `root * /var/www/anitech-performance`); смена пароля = выход со всех устройств. **Не перетирать эти правки в Caddyfile.** Исходники публичные — секретов на страницах быть не должно. `curl` без cookie на `/mira/` даёт 302, не 401. Не `curl | bash` сразу после правки скрипта: GitHub несколько минут отдаёт старую версию из кеша.
