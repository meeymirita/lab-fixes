**Решение владельца 17.10.2026.** Эталон лабы — Caddy Lab (формат, сессии, итоговое ТЗ, стиль шага). К нему теперь добавляется обязательное:
1. **Схемы** на ключевые места (8–14 на лабу; SVG на `currentColor`, светлая и тёмная темы).
2. **«Ожидаемый результат» с настоящим выводом** у каждого шага с запуском; где результата нет — заполнить. Не написанный по памяти: только из прогона. Где запустить нельзя (аккаунт, ключи, домен) — описание словами и пометка «не запускалось».

Пилот сделан на JS Lab (13 схем, прогон шагов 1.1–9.4, 7 результатов добавлено, 3 найдены технические ошибки) и принят владельцем. Образец и заготовки — `fixes/common/_tools/verify/`, схемы — `fixes/common/_tools/svgkit.py`, отчёт — `fixes/frontend/js.md` (раздел 17.10).

## Порядок работы над одной лабой (по JS-пилоту)
0. **Перед началом:** согласие владельца на Docker Desktop (запускать только с ним); записать списки образов, контейнеров, томов «до» (по ним потом удалять только созданное); рабочая папка `.manual-tmp/<лаба>-verify` внутри репозитория (в `.git/info/exclude`; Docker не монтирует `/tmp`); `COMPOSE_PROJECT_NAME` свой.
1. **Стенд из блоков методички** (`runjs.py`): файлы по первой строке-комментарию с путём, команды шагов по порядку; чужие процессы на портах (на Mac занят 3001) — менять только **хост**-порты в compose стенда, в методичке они остаются. Браузерные шаги — Playwright (запросы на занятые порты перенаправлять `page.route`), состояние каждого шага проверять на чистых файлах (удалять файлы поздних шагов перед проверкой ранних).
2. **Сверка** (`cmpjs.py`): вывод против `result` построчно; расхождения по таймингам и версиям — не ошибка; остальное исправлять **настоящим** выводом. Пустые `result` — заполнять.
3. **Найденное** — в методичку (`bundle.jsub`/`transform`), запись в `fixes/<направление>/<лаба>.md` («Найдено и исправлено», «Добавлено», «Не проверено»).
4. **Схемы**: выбрать 8–14 мест (потоки, жизненные циклы, где живёт состояние, порядок событий, архитектура, сравнения «до/после», структуры данных); нарисовать на `svgkit.py` (`Svg.box/arrow/bar/text/path`), собрать на одной предпросмотровой странице, снять скриншоты (`dshot.mjs`) и поправить наложения, обрезанный текст, стрелки; вставить после первого абзаца шага (`jsins.py`); стили `.diagram` добавляет `to_caddy.ensure_css`.
5. **Проверка:** `audit_manuals.py <лаба>`, `check-site.py`, `vcheck.sh` (текст до/после, ошибки страницы), схемы в реальной странице (размер, ошибки).
6. **Записи и git** (после каждой лабы отдельным действием): changelog, `_state-log.md`, `_verification.md` (строка лабы), `fixes/<направление>/<лаба>.md`, статус в README лабы, `_todo.json` (убрать пункт), генераторы (`build-toc/progress/seo/verification`); коммиты по порядку подмодуль → works → fixes → родитель, **перед `git add` подмодуля сверить HEAD с origin/main**; проверить Actions.
7. **Убрать за собой в Docker:** `docker compose down -v`, удалить образы, которых не было «до», закрыть Docker Desktop; сверить списки с сохранёнными.
8. **Итог владельцу:** что исправлено, что добавлено, **что ей проверить глазами**, что не проверено.

## Чему научил пилот (ловить заранее)
- Старые «Ожидаемые результаты» часто устарели (формат вывода Node 24, число тестов, прикидки в таблицах) — доверять только прогону.
- Блок «файл + демонстрация для консоли» в одном `<pre>` ломается при копировании целиком — разделять.
- Статический `import` в консоли браузера не работает; сервер должен отдавать `.mjs` как `text/javascript`.
- Голые таблицы в формате Caddy выглядят «сырыми» — стили таблиц, глоссария, врезок, схем лежат в шаблоне (`ensure_css`).
- Страницы-справки с пустым `html` при заполненном `gloss` — пустые; проверять `audit_manuals.py`.
- zsh не разбивает переменную со словами — списки лаб хранить массивом.
- Не доверять первой оценке «что сломано»: пустую страницу или ошибку проверять на исходной версии (git), а не считать результатом перевода.

## Напоминание себе
Если владелец просит новую лабу, расширение, переписывание или правку шагов — сначала сверить с этим планом: после стандарта Caddy у лабы должны быть схемы и настоящие результаты. Если их нет — сказать об этом в итоге и предложить место в очереди.
