# Инструменты прогона и оформления лаб (скопированы из рабочей папки сессии 17.10.2026)

Это **примеры и заготовки** из пилота на JS Lab, а не готовые универсальные утилиты: внутри зашиты пути к рабочей папке той сессии
(`/private/tmp/claude-501/.../scratchpad`) и к лабе JS. Перед использованием скопировать в новую рабочую папку и заменить пути/имя лабы.
Метод и порядок — `fixes/common/_plan-schemes-results.md`.

| Файл | Что делает |
|---|---|
| `runjs.py` | собирает стенд лабы из блоков методички (файлы по первой строке-комментарию с путём, команды `docker compose exec …`) и выполняет шаги по порядку; вывод — в JSON |
| `cmpjs.py` | сверяет настоящий вывод с полем `result` каждого шага (по строкам, расхождения показывает) |
| `jsfix.py` | образец правки: настоящие результаты в `result`, голые `<pre>` → `pre[data-lang]`, пересчёт поля `text` |
| `jsdiag.py` + `jsins.py` | образец схем (словарь «ключ шага → SVG» на `svgkit.py`) и вставки после первого абзаца шага |
| `dshot.mjs` | рисует все схемы на одной странице и снимает скриншоты для проверки читаемости (нужен Playwright) |
| `vt.mjs`, `vcheck.sh` | сравнение видимого текста шагов до/после правки (git HEAD против рабочего файла) и ошибок страницы |
| `bt.mjs`, `b7.mjs`, `css.mjs` | образцы Playwright-проверок браузерных шагов (запросы, консоль, вторая вкладка, computed style) |
| `patch.py`, `post.py`, `ship.sh` | дописать поля шага и пересчитать `text`; запись в changelog и журнал; коммиты и пуш по порядку подмодуль → works → fixes → родитель с проверкой указателей |
| `blk.py`, `ex.py`, `sh.py`, `sh2.py` | прочитать блоки кода/поля шагов, чтобы писать вопросы и схемы по тексту |

Скрипты исходно писались под zsh на macOS: переменная со списком слов не разбивается (использовать массив `L=(a b c)` и `$L`).
