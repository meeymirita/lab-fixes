# Порядок прохождения и зависимости между лабами

> **Решение владельца 05.10.2026:** источник истины по зависимостям и учебному порядку — `works/js/prereq.js` (то, что видно на сайте в окне «Что нужно знать до старта»); этот файл приведён к нему. Нумерация в корневом README и на карточках сайта — **другая**: по направлениям (витрина: фронтенд 1–7, бэкенд 8–18, инфраструктура 19–22). «Номер в витрине» ≠ «место в учебном порядке».

Составлено по тексту самих методичек (на что они ссылаются), а не только по README.
Сила связи: **жёсткая** — без предыдущей лабы шаги буквально не выполнить (нужен её код/образ);
**знания** — методичка объясняет новое через сравнение с предыдущей и пишет «как вы видели в …»;
**мягкая** — полезно, но не обязательно.

## Граф зависимостей

```
Docker ──знания──▶ Traefik ──ЖЁСТКАЯ──▶ Kubernetes
   (Kubernetes берёт api/ и образ traefik-lab-api:v1 прямо из Traefik-лабы)

OOP (php-coffee) ──знания──▶ RabbitMQ ──знания──▶ Redis
        │                        │
        └──────знания────────────┴──────▶ Laravel (TaskFlow)
                                               │
                                          знания (!) — см. конфликт №1
                                               ▼
                                         Чистый PHP

CSS ──▶ Tailwind ──▶ Чистый JS ──мягкая──▶ Vue ──знания──▶ TypeScript ──мягкая──▶ NestJS ──мягкая──▶ GraphQL
                       ▲              │                      │
                       │              └──знания──▶ Nuxt ──мягкая──▶ Angular
                       │                                     │
                       └──── «тот же домен Helpdesk» ────────┘  (контракты API НЕ совпадают, см. конфликт №2)
```

## Конфликты, которые надо решить

### №1 (важно). «Чистый PHP» стоит 3-м, а ссылается на Laravel-лабу, которая стоит 13-й
Корневой README: «Чистый PHP встал рядом с OOP», сложность «базовая», нужна только OOP-лаба.
Но методичка написана так, будто TaskFlow уже пройден: «вы уже пользовались Container… как потребитель
(Laravel-лаба)», «тот же код 419, что вы видели в Laravel-лабе при провале Sanctum CSRF-проверки».

Варианты:
- **А (проще):** переформулировать ссылки в PHP-лабе на OOP-лабу (там тоже Laravel 13 с сессии 5 — Container и
  роутер уже «видены как потребитель»), а ссылки на TaskFlow (Sanctum, withExceptions) оставить как
  «увидите потом в Laravel-лабе». Порядок в README не меняется.
- **Б:** передвинуть Чистый PHP после Laravel. Тогда логика «фундамент рядом с OOP» теряется.

Рекомендую А. Список всех мест — в `fixes/backend/php.md`.

### №2 (важно). Vue-фронт нельзя «направить» на NestJS-бэкенд без переделок
NestJS-методичка: «API спроектирован так, чтобы тот фронтенд [Vue Lab] можно было направить на этот бэкенд».
Корневой README: NestJS «собирает с нуля тот самый бэкенд, который в Vue-лабе был дан готовым».
Фактически контракты разные в 5 местах — таблица в `fixes/backend/nestjs.md`. Либо убрать обещание, либо добавить
в NestJS-лабу шаг «адаптер под Vue-фронт».

### №3. Порядок JS → Vue → TypeScript сейчас правильный, но README-абзац длинный и местами неверный
Абзац «Порядок — от простого к сложному…» в корневом README утверждает про NestJS то, что неверно (конфликт №2),
и не упоминает, что Kubernetes требует **код** Traefik-лабы, а не только знания.

## Учебный порядок (= `prereq.js`, ORDER; с вариантом А для конфликта №1)

| № | Лаба | Почему здесь |
|---|---|---|
| 1 | Docker | ни от чего не зависит, база для Traefik и Kubernetes |
| 2 | OOP (php-coffee) | фундамент PHP/Laravel |
| 3 | Чистый PHP | язык без фреймворка рядом с OOP (после правки ссылок) |
| 4 | Algorithms PHP | самостоятельна, нужен только синтаксис PHP; удобно проходить рядом с «Чистым PHP» и ООП |
| 5 | PostgreSQL | ни от чего не зависит — то, что во всех лабах было «за ORM» |
| 6 | RabbitMQ | после ООП (знания); пройдена владельцем |
| 7 | Redis | всё время сравнивает себя с RabbitMQ |
| 8 | Laravel (TaskFlow) | самая большая, опирается на ООП + RabbitMQ (+ Redis полезен) |
| 9 | Laravel Performance | самостоятельна, нужен лишь базовый Laravel; логичнее всего после Laravel-лабы |
| 10 | CSS | ни от чего не зависит, во фронтенд-треке первой — до Tailwind и JS |
| 11 | Tailwind | после CSS — строится на каскаде и box model |
| 12 | Чистый JS | фундамент фронта |
| 13 | Vue | после JS (полезно) |
| 14 | Inertia | предполагает Laravel и Vue — логичнее всего после них |
| 15 | TypeScript | сессия 5 использует Vue |
| 16 | Nuxt | после Vue и TypeScript — объясняет только то, что Nuxt добавляет поверх Vue |
| 17 | Angular | после TypeScript, во фронтенд-треке последней — теория сравнивает с Vue и Nuxt |
| 18 | NestJS | TS-минимум есть в сессии 1; полезно после TypeScript |
| 19 | GraphQL | основы Nest полезны |
| 20 | Traefik | после Docker (знания) |
| 21 | Caddy | самостоятельна; решает ту же задачу, что Traefik (reverse proxy, TLS), другим инструментом — логичнее рядом с Traefik |
| 22 | Kubernetes | **только после Traefik** — берёт её код (`api/`, образ `traefik-lab-api:v1`) |

Это учебный порядок. Нумерация в корневом README и на карточках сайта — по направлениям (витрина); обе нумерации — осознанно разные (решение 05.10.2026), на сайте они подписаны («номер в витрине» / «место в учебном порядке»).

## Стыки между лабами

Стыки (что одна лаба берёт у другой: код, образ, домен, термины, ссылки «как в X-лабе») проверялись 24–26.09 по трём цепочкам — Docker → Traefik → Kubernetes, JS → Vue → TypeScript, OOP → Чистый PHP → RabbitMQ → Redis → Laravel. Все найденные расхождения (ссылки на ещё не пройденные лабы, «Worker Kit», притяжательное «ваш», разные версии PostgreSQL и т. п.) исправлены в методичках; контрольная перепроверка 04.10 по ключевым фразам совпадений не нашла. Отдельные файлы `_chain_*.md` удалены как устаревшие. Жёсткая зависимость осталась одна — Kubernetes берёт код Traefik-лабы (`api/`, образ `traefik-lab-api:v1`).
