# Порядок прохождения и зависимости между лабами

Составлено по тексту самих методичек (на что они ссылаются), а не только по README.
Сила связи: **жёсткая** — без предыдущей лабы шаги буквально не выполнить (нужен её код/образ);
**знания** — методичка объясняет новое через сравнение с предыдущей и пишет «как вы видели в …»;
**мягкая** — полезно, но не обязательно.

## Граф зависимостей

```
Docker ──знания──▶ Traefik ──ЖЁСТКАЯ──▶ Kubernetes
   (Kubernetes берёт api/ и образ traefik-lab-api:v1 прямо из Traefik-лабы)

OOP (php-coffee) ──знания──▶ RabbitMQ ──знания──▶ Redis
        │                        │
        └──────знания────────────┴──────▶ Laravel (TaskFlow)
                                               │
                                          знания (!) — см. конфликт №1
                                               ▼
                                         Чистый PHP

Чистый JS ──мягкая──▶ Vue ──знания──▶ TypeScript ──мягкая──▶ NestJS ──мягкая──▶ GraphQL
                       ▲                                     │
                       └──── «тот же домен Helpdesk» ────────┘  (контракты API НЕ совпадают, см. конфликт №2)
```

## Что откуда следует (доказательства в тексте)

| Лаба | Зависит от | Сила | Где в методичке |
|---|---|---|---|
| Traefik | Docker | знания | Docker README: «то, на что в Traefik Lab был выделен всего один вводный раздел»; Docker-лаба заканчивается «точкой возврата к Traefik Lab» |
| Kubernetes | Traefik | **жёсткая** | шаг 1.4: «Каталог api/ с Dockerfile и server.js — тот же самый, что вы собрали в Traefik-лабе… Скопируйте его»; образ `traefik-lab-api:v1` |
| Kubernetes | Docker | знания | «Named volume из Docker-лабы (раздел 6.1)…» |
| Redis | RabbitMQ | знания | 10 сравнений: «Сравните с диаграммой RabbitMQ-лабы», processed_messages «ровно как в RabbitMQ-лабе», Outbox. Код не переиспользуется, но без RabbitMQ половина «почему» не читается |
| Laravel | RabbitMQ | знания | 10 ссылок на RabbitMQ-лабу (драйвер очередей, сравнения) |
| Laravel | OOP | знания | только в README («см. oop-lab»); в самой методичке OOP-лаба не упоминается ни разу |
| Чистый PHP | **Laravel (TaskFlow)** | знания | 22 ссылки: «Вы уже пользовались Container, Router, Eloquent как потребитель (Laravel-лаба)», «раздел 6.1 Laravel-лабы — Sanctum SPA CSRF», «Сравните свой Container.php с тем, что видели в Laravel-лабе» |
| Чистый PHP | TypeScript | мягкая | «тот же принцип… что strict в TS-лабе» |
| Vue | Чистый JS | мягкая | JS README: «Полезно проходить до Vue Lab и TypeScript Lab» |
| TypeScript | Vue | знания | README: «сессия 5 её использует»; в методичке — «как в Vue-лабе», финал «Vue Lab на TS» |
| NestJS | TypeScript | мягкая | TS-минимум для Nest объясняется в сессии 1 |
| GraphQL | NestJS | мягкая | README: «пригодятся основы NestJS (модули, DI, декораторы)» |
| PostgreSQL | — | — | самостоятельная: «ничего не импортирует из других лаб — общая только идея кофейни»; параллели с Eloquent (раздел 2.7) — для понимания, не обязательны |

## Конфликты, которые надо решить

### №1 (важно). «Чистый PHP» стоит 3-м, а ссылается на Laravel-лабу, которая стоит 13-й
Корневой README: «Чистый PHP встал рядом с OOP», сложность «базовая», нужна только OOP-лаба.
Но методичка написана так, будто TaskFlow уже пройден: «вы уже пользовались Container… как потребитель
(Laravel-лаба)», «тот же код 419, что вы видели в Laravel-лабе при провале Sanctum CSRF-проверки».

Варианты:
- **А (проще):** переформулировать ссылки в PHP-лабе на OOP-лабу (там тоже Laravel 13 с сессии 5 — Container и
  роутер уже «видены как потребитель»), а ссылки на TaskFlow (Sanctum, withExceptions) оставить как
  «увидите потом в Laravel-лабе». Порядок в README не меняется.
- **Б:** передвинуть Чистый PHP после Laravel. Тогда логика «фундамент рядом с OOP» теряется.

Рекомендую А. Список всех мест — в `fixes/php.md`.

### №2 (важно). Vue-фронт нельзя «направить» на NestJS-бэкенд без переделок
NestJS-методичка: «API спроектирован так, чтобы тот фронтенд [Vue Lab] можно было направить на этот бэкенд».
Корневой README: NestJS «собирает с нуля тот самый бэкенд, который в Vue-лабе был дан готовым».
Фактически контракты разные в 5 местах — таблица в `fixes/nestjs.md`. Либо убрать обещание, либо добавить
в NestJS-лабу шаг «адаптер под Vue-фронт».

### №3. Порядок JS → Vue → TypeScript сейчас правильный, но README-абзац длинный и местами неверный
Абзац «Порядок — от простого к сложному…» в корневом README утверждает про NestJS то, что неверно (конфликт №2),
и не упоминает, что Kubernetes требует **код** Traefik-лабы, а не только знания.

## Рекомендуемый порядок (с учётом варианта А для конфликта №1)

| № | Лаба | Почему здесь |
|---|---|---|
| 1 | Docker | ни от чего не зависит, база для Traefik и Kubernetes |
| 2 | OOP (php-coffee) | фундамент PHP/Laravel; ты сейчас на ней |
| 3 | Чистый PHP | язык без фреймворка рядом с OOP (после правки ссылок) |
| 4 | Traefik | после Docker |
| 5 | Kubernetes | **только после Traefik** — берёт её код |
| 6 | RabbitMQ | ✅ пройдено |
| 7 | Redis | всё время сравнивает себя с RabbitMQ |
| 8 | Чистый JS | фундамент фронта |
| 9 | Vue | после JS |
| 10 | TypeScript | сессия 5 использует Vue |
| 11 | NestJS | TS-минимум уже есть |
| 12 | GraphQL | основы Nest уже есть |
| 13 | Laravel (TaskFlow) | самая большая, опирается на OOP + RabbitMQ (+ Redis полезен) |
| 14 | PostgreSQL | добавлена 25.09; ни от чего не зависит — то, что во всех лабах было «за ORM» |

Это совпадает с текущей таблицей в корневом README — меняется только то, что PHP-лаба должна перестать
ссылаться на TaskFlow как на пройденную.
